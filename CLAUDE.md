# CLAUDE.md — Session Protocol for the Industry AI Landscapes portfolio

Three AI-disruption landscape dashboards — **gaming · FMCG · luxury** — built from the proven travel-industry methodology, populated over many sessions, deployed as one site with an industry toggle. This is a **portfolio project for the user's job applications**: quality and defensibility of the output matter more than speed. Context lives in files, not chat history.

## Start of every session (read in this order)

1. **PLAN.md** — the full roadmap. Skim to locate the current phase.
2. **PROGRESS.md** — the cross-industry status board. This tells you exactly where work stopped.
3. **Latest file in `sessions/`** — what happened last session.
4. **The active industry's `industries/<ind>/frame.md`** — its disruption frame, pillars, taxonomy. If its status is still `draft`, review it with the user before populating anything.
5. **DECISIONS.md** — before making a choice that might already be settled.
6. **Staleness check** (once an industry has data): compare each populated workbook's SHA-256 against its `industries/<ind>/data/extract_meta.json`; re-extract if different.

## Source-of-truth rules

- **`industries/<ind>/<ind>_landscape.xlsx`** is the source of truth for that industry's company data. The skeletons are generated by `scripts/make_workbook.py` — regenerate only while a workbook is still EMPTY (regenerating later destroys data; population edits must go through `scripts/populate.py` or Excel itself).
- **Derived scores (W%/D%/AI%/EPI/tier/quadrant) are computed in Python by `scripts/populate.py`** and written as plain values — never as Excel formulas (openpyxl extraction can't read uncomputed formula caches; this bit the travel project).
- `industries/<ind>/frame.md` is the source of truth for that industry's vocabulary (pillars, stages, taxonomy, benchmark). The signal definitions live in `scripts/make_workbook.py` (`INDUSTRIES` dict) and are baked into each workbook's Scoring Guide sheet — keep the two in sync; workbook wins on conflict.
- `template/` is the **untouched reference machinery** from the travel project. Never edit it in place — copy pieces out when adapting (per its ADAPTATION-CHECKLIST.md).
- `viz/*.html` and `industries/<ind>/data/*.json` are generated — never hand-edit.
- **No Amadeus client material may enter this repo**: no travel data, findings, client names, or the travel workbook. The methodology is ours; the travel engagement's content is not.

## Population rules (the multi-session core)

> **The mechanics live in `ORCHESTRATION.md`** — Opus plans/instructs/QA-gates, Sonnet agents research via `scripts/research_batch.js`, `populate.py` writes, `qa_check.py` gates. Read it before running a batch.
>
> **Crash safety (learned the hard way — two fleets lost to usage limits):** research agents write **one JSON file per company** to `industries/<ind>/batches/raw/` the instant that company is done, so a mid-run kill never wastes completed research. **First action of any session that follows an interruption:**
> ```
> ls industries/<ind>/batches/raw/*.json        # what survived
> python -X utf8 scripts/populate.py <ind> --from-raw
> python -X utf8 scripts/qa_check.py <ind>
> ```
> Then re-run only the companies still missing. Never assume a run's tokens produced data — check the workbook and `batches/ledger.md` first.

- Research agents fill workbooks **one industry at a time**, in batches of ~15–25 companies, scoring every signal 0–5 **against the workbook's Scoring Guide anchors** — never gut feel.
- **Every row carries evidence**: `Evidence links` (source URLs), `Evidence notes`, `Confidence` (H/M/L), `Researched on/by`. A row without evidence is a rumor, not data.
- **Calibration**: the first batch of each industry establishes ~5 anchor companies spanning the score range; every ~50 companies, re-check a sample against the anchors so 0–5 stays consistent across sessions.
- Company names: one canonical spelling per company (it's the join key everywhere); log aliases as you meet them. Duplicates → mark `Reviewer notes` starting with `DUPLICATE` (the extractor skips them).
- After every batch: update PROGRESS.md counts + append to the session log. **As you go, not at session end** — context can die at any moment.

## End of session / after every milestone (non-negotiable)

1. Update **PROGRESS.md** (counts, phase checkboxes, next action).
2. Append **`sessions/YYYY-MM-DD-session-NN.md`**: what was done, what was produced, open threads.
3. Decisions with the user → dated line in **DECISIONS.md** (append-only).
4. Industry insights → **FINDINGS-<industry>.md** with evidence pointers.
5. Commit + push (small commits per milestone; the repo is the memory).

## Conventions

- Scores cite like `(EPI 72, High, Imminent threat)`; analysis files live in `industries/<ind>/analysis/`, numbered, with a Status line.
- Dashboard work follows `template/ADAPTATION-CHECKLIST.md`; the header toggle (Gaming · FMCG · Luxury) is part of each build, linking `/gaming` `/fmcg` `/luxury`.
- Deployment target: one public repo (`industry-ai-landscapes`) + one Vercel project; AI simulator env vars per template README.

## Windows / PowerShell gotchas

- Always `python -X utf8` (data is full of non-ASCII).
- PowerShell 5.1: no `&&` (use `;`); write script files instead of `python -c` one-liners.
- Never save a **populated** workbook via openpyxl if it ever gains Excel formulas; scores are plain values by design so this stays safe.
