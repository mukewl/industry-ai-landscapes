This folder is a **multi-session market-intelligence project**. Context lives in markdown files, not in chat history. Follow this protocol every session.

## Start of every session (read in this order)

1. **PROJECT.md** — what this project is, objectives, glossary. Read once, skim on later sessions.
2. **STATE.md** — the living dashboard: what's done, in progress, and next. This is your entry point for "where were we?"
3. **Latest file in `sessions/`** — what happened last session.
4. **DECISIONS.md** — only if you're about to make a choice that might already be settled.
5. **Staleness check**: compare the SHA-256 hash of the Excel file against `data/extract_meta.json`. If it differs (or `data/` is missing), rerun:
   ```
   python -X utf8 scripts/extract_excel.py
   ```
   before doing any analysis. Never analyze from a stale extract.

## Source-of-truth rules

- **`<WORKBOOK_FILENAME>.xlsx`** is the source of truth for all company data. If the user adds a newer version, update `EXCEL_FILE` in `scripts/extract_excel.py` and note it in DECISIONS.md.
- **Markdown files** (analysis/, FINDINGS.md, DECISIONS.md) are the source of truth for analysis, insights, and decisions.
- **`data/*.json`** is machine-generated. NEVER hand-edit it — fix the script or the Excel instead. Exception: `data/relationships_manual.json` (curated edges, hand-maintained by design).
- **`viz/dashboard.html`** is generated by `scripts/build_dashboard.py` — never hand-edit; change the script and rebuild.

## End of session / after every milestone (non-negotiable)

1. Update **STATE.md** (move items between Done / In progress / Next; keep it short — it's a dashboard, not a log).
2. Append a session log to **`sessions/YYYY-MM-DD-session-NN.md`**: what was done, what was produced, open threads.
3. Any decision made with the user → one dated line in **DECISIONS.md** (append-only, never rewrite history).
4. Any insight/pattern discovered → entry in **FINDINGS.md** with an evidence pointer (company names + which columns support it). Findings without evidence pointers are not findings.

Update these *as you go* for long sessions — context can be lost at any moment; the file system is what survives.

## Data reliability warnings

<!-- Record any column known to be unreliable/incomplete here, as discovered. -->
- Rows whose `Reviewer notes` start with `DUPLICATE` are excluded by the extractor.
- `Reviewer notes` is the audit trail for workbook edits made in this project — read it before re-scoring anything.
- Always back up the workbook to `backups/` before editing it, and edit via **Excel COM** (PowerShell), never openpyxl save — openpyxl strips cached formula values (the computed score columns are formulas).

## Conventions

- Company names: use exactly the spelling in the `company` field of `data/companies.json` so everything stays joinable.
- Analysis files live in `analysis/`, numbered by workstream. Each starts with a **Status** line (`draft` / `reviewed by user` / `final`) and a **Last updated** date.
- Cite data like: `(<INDEX> 78, High threat, <quadrant>)` — every claim about a company must be traceable to its row.
- Don't re-derive what's already in FINDINGS.md — build on it.

## Windows / PowerShell gotchas (if on Windows)

- Python prints non-ASCII (·, —, →) everywhere in this data: always run `python -X utf8`.
- PowerShell 5.1 strips inner double quotes in `python -c` one-liners — write script files under `scripts/` instead.
- PowerShell 5.1 has no `&&` — use `;`.
