# Session 02 — 2026-07-13 — iGaming + the orchestration system (Phase B)

## What was done

### 1. iGaming added as industry #1 (D6, D7)
Video gaming moves to #2; lineup is now iGaming → gaming → FMCG → luxury.
- **Frame**: *player ownership & acquisition* — "Who can use AI to own the player relationship and bypass the licensed operator?" Incumbent = the licensed multi-brand operator + its affiliate-SEO acquisition rail. Benchmark `{w:35, d:90, ai:40}`. Pillars **Player / Product / Wallet**.
- **Workbook**: 116 columns — the shared 111 plus 5 iGaming-specific PROFILE fields (licensed jurisdictions, regulated revenue %, locally regulated markets count, responsible-gambling stance, crypto accepted), so the regulatory axis is captured without spending the 5 vertical slots on it. Verticals are **product** verticals (Sportsbook · Casino & slots · Live casino · Poker & bingo · Lottery & emerging).
- `frame.md` (why-now evidence, taxonomy with colors, scenario seeds) and `seedlist.md` (~150 ranked candidates across 8 sectors, 5 designated calibration anchors).
- `make_workbook.py` gained `extra_profile` support, a `sectors`/`pillars` vocabulary per industry, and a `write_brief()` that generates `researcher_brief.md` — so the agent brief, the workbook Scoring Guide and populate.py cannot drift apart.

### 2. The orchestration system (D8, D9) — the reusable deliverable
Opus plans/instructs/QA-gates; **Sonnet** agents research at breadth. Documented in `ORCHESTRATION.md`.
- `scripts/research_batch.js` — Workflow fan-out (N agents × 5 companies), strict JSON output schema, full research protocol + scoring discipline inlined in the prompt.
- `scripts/populate.py` — maps rows → the 116 columns, computes W%/D%/AI%/R/EPI/tier/quadrant/financial-health **in Python as plain values** (never Excel formulas), idempotent (re-running a company updates, never duplicates), appends to `batches/ledger.md`.
- `scripts/qa_check.py` — evidence coverage, score ranges, EPI/quadrant recomputation, duplicates/near-duplicates, sector vocabulary, distribution sanity, **anchor drift** (>8 EPI pts = FAIL). Non-zero exit on any FAIL.
- `.claude/agents/company-researcher.md` — the agent definition (kept as documentation; see D9).

**Two bugs found and fixed at zero token cost**: workflow `args` can arrive as a JSON string (now parsed defensively), and a custom `agentType` does not resolve when the session's project dir differs from the project folder (now uses `model: 'sonnet'` with the protocol inlined).

## Key surprises / findings

- **Frame discipline is working.** Bet365 has the batch's joint-highest distribution (94) but scores *Sleeping giant* (EPI 48) because willingness is 27 — while DraftKings, far smaller in distribution (70), scores higher overall (60). The agents scored the frame, not company size.
- **Betsson — the named reference incumbent — lands low (EPI 38, Dormant).** That is the frame working as designed: it is the model being disrupted, not a disruptor.
- **AI readiness is genuinely low across iGaming** (16–55, mean ~31). Sportradar tops it at 55. Worth a FINDINGS entry: the sector talks about AI far more than it ships it.
- **Willingness is doing the discriminating work** (spread 9–91) — appropriate for a "who will attack the incumbent" frame.
- **Accepted deviation**: the seed list predicted Evolution would be a *Sleeping giant*; research put it at *Dormant* (EPI 26) because it has no player-facing platform or payments rails at all. The researched value became the anchor; the prior was wrong.

## The session-limit incident (recorded so it isn't repeated)

The first full 25-company fleet run **hit the usage limit mid-flight**: 5 agents, 237k tokens, 54 tool calls — and returned **zero rows**. The journal contained only `started` entries; agents never got to emit their structured output, and **nothing is persisted until `populate.py` runs**. Recovery was to verify state (workbook empty, no ledger, no batch files → no dedupe risk) and re-run smaller. Lesson now written into PROGRESS.md and CLAUDE.md: **keep batches ~10–25 and always check the workbook + ledger before re-running.**
